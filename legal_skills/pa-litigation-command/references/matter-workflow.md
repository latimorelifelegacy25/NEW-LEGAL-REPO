# Matter Workflow

Keep each legal task inside one identified matter boundary.

## Matter start

Confirm or derive:

- caption and docket;
- court/division;
- parties and roles;
- current procedural posture;
- operative pleading/order/request;
- task requested;
- source set being relied upon.

If two matters share facts, do not silently import a fact, ruling, exhibit, or deadline from one docket to the other. Identify the cross-matter source explicitly.

## Source inventory

For a substantial filing/review, maintain a working source table with:

| Source | Date | Matter | What it proves | Exhibit/record cite | Confidentiality |
|---|---|---|---|---|---|

Mark contradictions and later corrections instead of deleting the earlier version from the working record.

## Filing/document state

Distinguish drafts, served copies, filed copies, amended/superseded pleadings, exhibits, and court-entered orders. Never treat an unsent draft as filed or a superseded attachment as operative merely because it is the newest file in a folder.

## External platforms/connectors

Use a connected legal/document platform only when actually available and the user has authorized that use. Do not state that an unavailable connector reviewed, uploaded, indexed, or stored material.

## End state

A completed task should leave:

- a usable draft/audit/answer;
- source provenance;
- unresolved conflicts clearly flagged;
- current-authority checks documented where legal propositions matter;
- next filing/service step distinguished from actions already completed.
